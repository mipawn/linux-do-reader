# LINUX DO 阅读器

适用于 ego lite、Chrome 和 Edge 的第三方浏览器扩展。**仅增强 `https://linux.do/` 首页**：在首页原地阅读树状讨论，使用原版编辑器回复。其余页面保持 Linux.do 原版。

- **仅限首页**：不接管 `/latest`、类别、标签、`/t/...`、`/topic/...`、登录或账号设置等页面；从首页离开时移除阅读器并恢复原版布局、配色和 Logo。
- **原地阅读**：普通点击首页列表标题，在同一首页打开树状讨论，不修改 URL。`⌘/Ctrl + 点击`、中键、右键及楼层链接仍打开原版页面。
- **原版回复**：话题工具栏与可用楼层提供「回复」，交给 Linux.do 自带编辑器处理登录、权限、草稿恢复、草稿切换确认、预览和实际提交。扩展不自行发送回复或自动重试提交。
- **正在回复**：观察原站 MessageBus 的 presence 事件，显示其他正在撰写回复的用户或匿名人数；不会因为阅读而登记自己正在输入。
- **实时更新**：新回复、已加载楼层编辑及明确删除由原站事件驱动更新；没有另开的轮询器。合并更新并保留当前阅读位置、排序和折叠状态，限流或网络失败时显示暂停与手动刷新入口。
- **回复树与分页**：支持折叠、删除占位、最早 / 最新 / 最多赞排序和按需加载。打开话题默认使用「最早」（正序），排序切换仅对当前话题生效，不自动读取列表第一篇。
- **话题统计**：列表与阅读区明确显示回复、浏览量文字标签；回复总数优先采用原站 `posts_count - 1`，零值正常显示，统计不依赖首楼是否可用。
- **原站投票**：首楼与回复楼内支持单选、多选、数字评分及多份投票，显示真实参与人数和允许查看的结果；单选 / 评分点击即提交，多选选择后点击「提交投票」，已投可修改或取消。尊重原站登录、用户组、归档、截止时间与结果可见性规则，公开投票明确标注；写入走原站接口与 CSRF、共用限流队列且不自动重试。排名投票提供原站入口，不冒充完整支持。
- **原版互动信息**：在楼主内容和每个可用楼层下方显示原站的**表情回应**（最多 3 个表情 + 回应总数）、**表情评论**（头像 + 短评气泡）和**相关链接**（被其他帖子引用的话题，超过 5 条可展开）。只读取已有数据渲染，不新增请求。
- **直接互动**：回应栏可直接切换原站启用的表情，普通点击点赞，悬停或长按打开原版顺序的表情面板；再次点击自己的回应可取消。「表情评论」按原站 `can_boost` 权限开放：主题首楼、没有短评的楼层和已有别人短评的楼层都可提供入口；已有短评时入口在气泡列表尾部。短评最多 16 个字、5 个表情，可使用原站自定义表情。自己的短评可删除，删除后恢复入口。所有写入都走原站接口与 CSRF，只有明确点击才发送；登录、权限、撤回期限和限流以原站为准，失败会提示且不伪造成功。
- **图片预览**：普通点击正文图片或图片说明，在当前页面仅预览点击的这一张，不切换其他图片。点击空白处、Esc 或关闭按钮退出；提供放大 / 缩小 / 重置按钮及 `+` / `-` / `0` 快捷键，鼠标滚轮或触屏双指可缩放，放大后可拖动查看。Ctrl/Cmd 点击、中键和「打开原图」仍保留原图访问，头像、表情和普通外链不被接管。
- **不做阅读同步**：扩展不累计或上报停留时间，不额外登记浏览，不写已读标记；旧同步开关不再生效。

## 安装与更新

1. 从 Releases 下载已发布的安装包并解压，或者加载当前源码目录。当前源码版本为 **1.7.10**，是否已发布以 Releases 为准。在 macOS 上，可把解压后的文件夹放在 `~/Library/Application Support/Linux DO Reader`；该目录应直接包含 [manifest.json](<manifest.json>)。
2. 在 ego lite 或 Chrome 打开 `chrome://extensions/`，或在 Edge 打开 `edge://extensions/`。
3. 打开「开发者模式」，点「加载已解压的扩展程序」，选择包含 [manifest.json](<manifest.json>) 的文件夹。macOS 文件选择窗口可用 `⌘⇧G` 输入目录路径。
4. 打开或刷新 **Linux.do 首页**，默认启用阅读器。页头可切换「阅读器 / 原版」。在其他页面点击扩展图标，会新开首页，而不是接管当前页面。

浏览器持续从选中的文件夹读取扩展，需要保留该文件夹；ZIP 解压后可删除。更新时把新版覆盖到已加载的固定目录，在扩展管理页点「重新加载」，再刷新 Linux.do。新版增加了原站桥接脚本，只刷新网站、没有重新加载扩展，不足以完成升级。

## 使用

- 顶部可切换话题、收藏、关注。「最新」下拉可以换列表，「筛选」可组合类别和标签，按 `/` 聚焦搜索框。这些操作仍留在首页。
- 「原站导航」保留社区、资源、类别、标签和自定义侧栏项目；真实导航到非首页时立即返回原版。页头原有通知、聊天和用户菜单不替换。
- 普通点击话题标题显示双栏树状讨论；「返回列表」关闭当前讨论，取消其未完成读取并释放该话题的实时订阅。阅读区 `Esc` 或页头「原版」隐藏阅读器；重新打开首页仍默认启用。
- 话题工具栏的「回复」回复整个话题；楼层底部的「回复」回复该楼层。已删除、隐藏或不可用内容不提供回复操作。原站登录与权限判定仍是最终依据。
- 帖子底部动作栏参照原版：约 40px 的主回应按钮，未回应时点赞、已有回应时取消当前回应，立即显示反馈，只让当前帖子进入忙碌状态；鼠标悬停或触屏长按可打开原站启用表情的面板；主按钮聚焦后按 `↓` 也可打开，Esc 关闭并返回主按钮，不再显示重复的「＋」入口。服务端失败时会恢复点击前状态并提示，不会把失败伪装成成功。主题首楼和楼层都有「表情评论」，已有其他人的短评时入口位于气泡尾部；权限以原站 `can_boost` 为准。短评编辑器可点选自定义表情或直接输入/粘贴表情，回车发布、Esc 取消。自己的短评可删除，其他仍存的气泡不妨碍恢复入口。写入请求与阅读共用限流保护，遇到限流会明确提示，不会自动重试。
- 原版编辑器负责草稿和提交。扩展只在自己打开的首页回复会话中临时保留首页位置；不会拦截其他原版编辑器会话。切换原版、打开其他编辑器、离开首页或页面卸载时撤销该会话的保护。需审核的回复不冒充已经发布。
- 有其他用户输入时，阅读区顶部独立一行显示头像、名字和「正在回复」，**不需要打开回复框**。初次快照尚未取得时显示未同步，已同步但无人输入时显示「暂无其他人正在回复」，不把未知状态当成零人。原站的 `last_message_id: null` 表示频道尚无消息记录，按原版规范接受，不把它误判成无效响应，也不据此强行判定无人。presence 响应或网络异常只在「正在回复」一栏降级，不停止正文增量更新；「重试正在回复状态」只补这一项快照，不重读话题。原站关闭 presence 或无权限时明确提示不可用，不启动后台重试循环。原版编辑器自身产生的输入状态由 Linux.do 管理。
- 树中每楼标注浏览器本地时区的发布时间。分支旁的加减号可折叠，点击「回复 #楼层」定位父楼层，楼层编号打开原版对应位置。
- 「最早」「最新」「最多赞」作用于同级分支并递归应用，与原版 Nested Replies 的排序语义对齐：「最早」按楼层号升序，「最新」按该楼发布时间降序，「最多赞」按该楼点赞数排序，而不是按分支最后活动时间。除链接中显式携带的 `sort` 参数外，打开话题默认使用「最早」（正序）；切换排序仅对当前打开的话题生效，不跨话题继承，也不读取或修改原版排序偏好。切到「最新」会从话题游标末尾补取一页尚未加载的最新回复，后续分页由新到旧读取。切回「最早」从最早的未加载回复继续读取。「最多赞」仍只根据已加载回复排序，不冒充全帖服务端排名；原版置顶、可见性和已加载范围也可能使两边显示不同。实时更新时保留当前阅读楼层的视口位置。
- 明确删除的楼层显示 `[已删除]` 并保留子回复，不渲染旧正文或作者身份。缺失或未返回的楼层显示「未加载或不可用」，不会仅凭缺失就断定删除。
- 接近底部约 300px 时按需加载；初次自动补读至多一页，之后每次继续滚动至多补读一页。布局变化、保留阅读位置或 Observer 通知不连续追读整帖；短页或折叠分支可点「加载更多」。同一分页只发一个请求，连续三批没有新增可见内容或分页地址重复时明确暂停。加载中的同一话题重复点击不重新 GET。

### 实时更新与限流

- 共用 **Linux.do 已有 MessageBus**，不新建长轮询连接、不改变原站轮询间隔，只移除阅读器自己的回调。
- 仅内容事件触发读取；点赞、阅读状态和统计事件不额外请求正文。新回复通常合并约 1 秒后读取，同一话题会话的自动更新请求开始至少间隔 **5 秒**，按批增量取楼层而不是每次重读全帖。
- 初次「正在回复」快照及丢消息后的恢复也走扩展请求队列。消息游标有缺口或手动刷新时，补一次话题快照，并分批核对已加载但未包含在快照中的楼层，避免漏掉历史楼层的编辑。空响应或不可用 presence 不反复重试。
- 正文、列表、分页及元数据在本标签页共享一个串行队列，默认按至少 **2 秒**间隔预约启动；同站点标签页共享启动时间，可用 Web Locks 时短锁内原子预约，不在锁内等待 HTTP，无 Web Locks 时只做尽力协调。原站自身和其他扩展的请求不受此队列控制。阅读器隐藏、切换话题或离开首页时取消自动更新；隐藏标签页只收集事件，恢复可见后按需追更。
- HTTP 429 / JSON 限流与带 `Retry-After` 的 502/503/504 分开提示，保留服务端更长截止时间。真实限流即使只要求等 1 秒，阅读器也增加至少 **5 秒**的本地保护，并将后续安全间隔提高到 **4 秒 / 8 秒**；该状态在标签页间共享，约 10 分钟无新限流后到期。冷却期间被拦的点击明确显示「本次未向原站重新请求」，不视为又一次 429、不延长处罚；倒计时结束后仍须手动恢复。截止时间和触发等待的白名单来源同样共享，未知来源不冒称限流。
- 阅读区「请求记录」可查看本页最近 10 次阅读器请求的时间、分类、前后台、方法与结果；不含网址、搜索词或正文，不上传，也不涵盖原站自身或其他扩展的请求。这能定位哪次请求收到限流，但不能证明此前哪次操作累积触发了服务端阈值；JSON 限流统一记为结果码 429。原版草稿/编辑器只记录已反馈的限流或服务端等待失败，其时间是收到失败的时刻，不是原版请求起始时间。
- 自动实时读取、自动分页和后台元数据 **不自动重放**。限流或正文读取网络失败后，即使收到新消息、倒计时结束，也要点击「更新回复」或「重试实时更新」恢复；仅 presence 失败可单独手动恢复，真实 429 或共享冷却仍暂停所有读取。普通前台读取遇到无服务端等待指令的短暂网络故障或 502/503/504，至多恢复一次；写入永不自动重放。
- 收藏和主题通知仅在点击时写入原站账号。编辑器草稿读取、自动保存和回复提交由 Linux.do 原版机制负责；已知扩展限流期间不再打开新回复。

固定配色仅在首页阅读器显示时覆盖网页，回原版后恢复原站配色。扩展自身不发送阅读时间或额外浏览登记；原版页面的阅读记录和统计由 Linux.do 处理。

## 开发与打包

仓库根目录可直接作为未打包扩展加载。使用原生 JavaScript 和 CSS，无需安装依赖。

```sh
node --test tests/*.test.mjs
python3 scripts/package.py
```

测试覆盖严格首页及 SPA 清理、原版编辑器与草稿/权限、原站消息游标和 presence、增量更新与取消、回复树、限流队列及 Observer 分页。测试使用内存原站模型，不会在真实论坛发表回复。

[打包脚本](<scripts/package.py>) 在 `dist/` 生成本地 ZIP，包含运行时文件、许可证、使用与隐私说明，[manifest.json](<manifest.json>) 位于 ZIP 根目录。该命令不发布 Release。
